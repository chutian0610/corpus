# 检索路线：图检索（PPR）先行，向量与混合检索排后续版本

行业默认做法是向量 RAG，但竞品 obsidian-llm-wiki 的数据表明在 wikilink 密集的 Wiki 场景中 Personalized PageRank 优于 kNN（PPR@5 27.1% vs 24.1%），且零向量管道依赖。我们决定首发版本只做"词法快匹配 → PPR 图扩展 → LLM 综合成答"三级级联；向量检索与混合检索各自作为后续版本的独立目标实现。"零 embedding"是首发版本的排期决策，不是被永久排除的架构立场。

## Consequences

- 后续引入向量检索时，需要设计图 / 向量两种检索分数的融合方案（即"混合检索"版本的目标）。
- 首发版本的检索质量上限受 Wiki Graph 链接密度制约，稀疏区域的召回弱——靠 Alias 强制与 lint 孤儿页检测疏导。
